Web accessibility, in short

Accessibility means people with disabilities — visual, auditory, motor, or cognitive — can perceive, understand, navigate, and interact with a page, usually with the help of assistive technology (screen readers, voice control, switch devices, magnification, keyboard-only navigation). It's built on four principles, known by the acronym POUR:

Perceivable
Content must be presentable in ways every user can perceive: text alternatives for images, captions/transcripts for audio and video, sufficient color contrast, and text that can be resized without breaking the layout.
Operable
Every interface element must be operable by any input method: full keyboard access with a visible focus indicator, no time limits that can't be extended, no content that flashes enough to trigger seizures, and clear ways to navigate (landmarks, skip links, descriptive headings).
Understandable
Information and interface behavior must be understandable: readable, predictable, consistent navigation, and clear labels plus helpful error messages on forms.
Robust
Content must work reliably across current and future browsers and assistive technologies — which in practice means valid, semantic HTML and correct ARIA usage, not just visual styling.

A practical checklist

  • Give every meaningful <img> a descriptive alt attribute (empty alt="" only for purely decorative images).
  • Label every form control with a visible <label>, aria-label, or aria-labelledby.
  • Never rely on color alone to convey meaning — pair it with text, an icon, or a pattern.
  • Meet WCAG AA contrast: at least 4.5:1 for normal text, 3:1 for large text.
  • Make every interactive element keyboard-reachable, with a visible focus style (don't remove outline without a replacement).
  • Use real, sequential heading levels (h1–h6) — don't skip levels or use headings just for visual size.
  • Structure pages with semantic landmarks (<header>, <nav>, <main>, <footer>) instead of generic <div>s.
  • Give links and buttons descriptive, unique accessible names ("Read pricing details", not "Click here").
  • Set a lang attribute on <html> so assistive tech uses the right pronunciation.
  • Test with just a keyboard (Tab / Shift+Tab / Enter / Space), and ideally a screen reader too.
